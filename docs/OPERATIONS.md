# 部署与运维

## 启动和停止

在专用非 root 用户下运行。每个市场独立 state 目录和配置，不同进程不能共用同一数据库。启动示例见 README。重复启动同 state 时文件锁阻止第二个进程推进行情，但当前 CLI 不提供专门重复启动错误码，监控应检查真实 socket health，不能只看命令退出状态。

正常停止使用 SIGTERM/SIGINT；服务停止接入后等待已有请求最多 30 秒，再保存与关闭。客户端应预留渲染时间。不要直接删除运行中的 socket、锁、数据库或 WAL。

`deployment/sharemarket@.service` 是 systemd **用户级示例**，使用 `%h/virtual-group-sharemarket`。部署者应修改工作路径并按实例设置私有配置后，才自行启用；本仓库不会自动安装或启动服务。

## 权限

服务启动设置 umask 077，state 目录创建权限 0700，socket 0600。已有目录权限需部署者检查。不要将同 UID 访问能力误认为强账号隔离，不要将 socket 转发到 HTTP、公网或不可信容器。

生产 `config/local*.json`、环境变量、日志、state、备份、数据库及新闻缓存不可提交 Git。日志可能包含业务错误及操作状态，也应按私密数据处理。不要把日志直接贴到公开 issue。

## 备份与恢复

管理私聊 `admin.backup` 调用数据库一致性备份。也可在完整停止进程后离线复制整个 state 目录和私有配置。运行中不能仅复制主 SQLite 文件而忽略 WAL。备份包含用户和隐藏市场状态，必须限制权限并加密存储。

恢复前停进程、备份现有目录，再恢复一致的完整备份；使用相同模型版本与代码，启动后检查 health 和 `admin.audit`。执行中断时先查询原 operation ID。平台发送成功但未 ACK 的结果需要平台核对，不能直接重发或重新交易。

## 清理与监控

定期检查 health、磁盘、SQL 审计、outbox 未确认量、渲染错误及新闻积压。引擎有历史保留与图片清理；未确认 outbox 引用的图片受保护，异常积压需要恢复而非粗暴删除。新闻 SQLite 的生命周期与备份也需宿主维护。

实时模式日历到期前必须更新；24 小时加速模式无需实际交易日历。升级前在临时目录跑回归与 smoke，备份数据库。模型版本和规则改变可能影响仿真行为，不承诺跨任意版本直接替换。
